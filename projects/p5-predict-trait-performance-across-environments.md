# Predict Trait Performance Across Environments

> The experiential core of Phase 5. You take a real multi-environment trial, build a genomic-prediction model that *respects* genotype-by-environment interaction (environment as a factor, then marker-by-environment / reaction-norm terms), and evaluate it the way a breeder actually deploys it: by predicting into an environment the model never trained on. This is as close as the curriculum gets to real breeding work — the verdict is not a pooled R², it is "would I trust this prediction to rank lines in a field I have not yet phenotyped?"

## Why this project

Phase 4 left you able to fit a genomic-prediction model and report one accuracy number on a random hold-out. A breeder cannot use that number, because a variety is not deployed into a random sample of its own training rows — it is deployed into a *new environment*, often a new year or a new location in the target region. If genotype rankings change across environments (and for yield they almost always do), a single pooled model predicts an average that may describe no real field, and a random-hold-out accuracy silently rewards the model for memorizing environments it has already seen.

This project forces the full G×E reasoning chain into code. You will fit a baseline that ignores G×E, then a model that adds environment as a main effect, then a model that lets marker effects vary by environment (the marker-by-environment decomposition) or that ties genotypes to environments through a reaction norm. The honest test is **leave-one-environment-out** cross-validation: train on a subset of environments, predict every genotype in a held-out environment, and ask whether the G×E-aware model recovers the ranking changes the pooled model averages away. The deliverable that says "I can do genomic prediction across environments" is proving you can take a multi-environment trial to a defensible cross-environment evaluation and say, per environment, where modelling G×E helped, where it did not, and why.

**This project is the working seed for the Phase 4 capstone, [[project-2-genomic-prediction-benchmark|Genomic Prediction Benchmark]].** The cross-validation harness, the model-comparison table, and the accuracy-bookkeeping you build here are exactly the infrastructure that capstone scales up to a full benchmark of methods; here you add the cross-environment dimension the single-environment benchmark omits. Build the leave-one-environment-out loop cleanly and it transfers directly.

## Setup

- **Language / tools:**
  - **R** is the path of least resistance: **sommer** (Covarrubias-Pazaran 2016, "Genome-assisted prediction of quantitative traits using the R package sommer"; CRAN, [`sommer.gxe` vignette](https://cran.r-project.org/web/packages/sommer/vignettes/sommer.gxe.html)) for mixed-model G×E with explicit between-environment covariance structures (compound symmetry, diagonal, unstructured, factor-analytic), and **BGLR** (Pérez & de los Campos 2014, "Genome-Wide Regression and Prediction with the BGLR Statistical Package," *Genetics* 198(2):483–495; CRAN) for the Bayesian marker-by-environment and reaction-norm models. (Confirm current package APIs and function names when you start — see gaps.)
  - **Python** alternative for the wrangling, cross-validation harness, and plotting (`pandas`, `numpy`, `scikit-learn` for ridge/GBLUP-by-hand, `matplotlib`/`seaborn`); you can fit the linear-algebra GBLUP and a marker-by-environment ridge yourself, but the ready-made G×E covariance structures live in the R packages, so a mixed R+Python workflow is reasonable.
- **Data:** The **BGLR `wheat`** dataset — **599 historical CIMMYT lines** from the Global Wheat Program, genotyped with **1447 DArT markers**, with **grain yield evaluated across 4 mega-environments** (the `wheat.Y` matrix is 599 × 4, standardized to unit variance within each environment) plus a pedigree-derived relationship matrix; it ships in the BGLR R package (`data(wheat)`; docs at [rdrr.io/cran/BGLR/man/wheat.html](https://rdrr.io/cran/BGLR/man/wheat.html), source `gdlc/BGLR-R`). This is the canonical MET panel used in the G×E genomic-prediction literature (Burgueño et al. 2012; López-Cruz et al. 2015; Cuevas et al. 2017), so your results have published baselines to sanity-check against. The same 599-line panel is also packaged as **`DT_wheat`** in **sommer**, and sommer's smaller **`DT_example`** (41 potato lines across 3 environments, RCBD, tuber-quality trait) is a clean toy MET to debug your harness on before scaling up. Pick the BGLR `wheat` panel as the primary dataset. (Verify both datasets still ship in the current package releases before relying on them — see gaps.)
- **Environment:** Reproducible renv/conda environment with a committed lockfile, fixed random seeds (the Bayesian models in BGLR are MCMC — set the seed and report enough iterations/burn-in for convergence), and a clean separation between the cross-validation harness and the model code so a fold's test environment can never leak into training.

## Milestones (each ends in a predict-then-check)

1. **Read the MET as the data structure it is.** Load the panel; lay out the genotype × environment table of phenotypes; compute the genetic correlation between each pair of environments and make the genotype interaction plot (one line per genotype across environments, environments ordered by their mean). *Predict before you compute: which pair of environments will be most genetically correlated, and will any genotype's line cross another's (a crossover interaction)? Then check — the between-environment correlations decide how much a G×E model can borrow, and a low correlation is exactly where a pooled model will fail.*
2. **Fit the no-G×E baseline (single-environment + naive pooled).** Fit GBLUP within each environment separately, and a single pooled GBLUP that ignores environment entirely. *Predict before you run: will the pooled model out-predict or under-predict the within-environment models on a random hold-out, and why? Then check, and note that random hold-out is the metric you are about to abandon.*
3. **Add environment as a main effect (the across-environment mean model).** Fit a model with a genotype main effect and an environment main effect but **no interaction** (the classic "main effects only" MET model). *Predict before you run: in which environment will a main-effects-only model mis-rank genotypes the most — and tie that prediction to the crossover you found in milestone 1.*
4. **Fit the G×E model: marker-by-environment and/or reaction norm.** Fit a model that lets marker effects have a shared main effect plus an environment-specific deviation (the López-Cruz et al. 2015 M×E decomposition, available in BGLR), and/or a reaction-norm model where the genotype effect interacts with the environment through a covariance structure (Jarquín et al. 2014 / Cuevas et al. 2017; or a factor-analytic / unstructured between-environment covariance in sommer). *Predict before you run: by how much will modelling G×E lift accuracy relative to the main-effects model, and in which environment — the one with the highest or the lowest correlation to the others? Then check.*
5. **Evaluate into a NEW environment — leave-one-environment-out cross-validation (the headline test).** Hold out one entire environment, train all four model classes on the rest, predict every genotype in the held-out environment, and record per-environment predictive correlation; repeat holding out each environment in turn. *Predict before you run, for each held-out environment: will the G×E model beat the pooled model, and where will even the G×E model struggle (which is the least-predictable environment from the others)? Then check, and write the per-environment verdict — including any environment where the simpler model won and why.*
6. **Interpret stability and write the verdict.** For the top predicted lines, separate predicted *mean* from predicted *stability* (e.g. a Finlay–Wilkinson regression slope on the predicted values, or the spread of predicted breeding values across environments); identify a line that is high-mean-but-unstable versus high-mean-and-stable. *Predict before you compute which of your top-ranked lines is the riskiest to release region-wide; then check against the stability statistic, and state which line you would actually recommend and for which target environments.*

## Deliverables

- [ ] **G×E model** — a fitted marker-by-environment and/or reaction-norm genomic-prediction model (sommer and/or BGLR), with the no-G×E baseline and main-effects-only model alongside it for comparison, runnable from the raw packaged data.
- [ ] **Cross-environment prediction evaluation** — the leave-one-environment-out results: a table of per-environment predictive accuracy for each model class, with the honest statement of where G×E helped and where it did not. This is the deliverable that distinguishes this project from a single-environment benchmark.
- [ ] **Stability interpretation** — predicted mean vs predicted stability for the top lines, and a one-paragraph recommendation that names a line and a target set of environments, justified by both mean and stability (not mean alone).
- [ ] **Short write-up (a `post` candidate — feeds the writing loop):** "Predicting into an environment I never trained on — what G×E modelling buys, and where it does not," centered on the gap between pooled accuracy and cross-environment deployability.
- [ ] Notebook / script (committed) — full pipeline, data load through cross-environment evaluation and stability plots; feeds the [[project-2-genomic-prediction-benchmark|capstone benchmark]].
- [ ] **Figures** (interaction plot, between-environment correlation heatmap, per-environment accuracy bars, stability/Finlay–Wilkinson plot) — candidates for a `docs/` D3 visualization via `biostat-viz`.

## Stretch goals

- Add a **reaction-norm model driven by environmental covariates** (Jarquín et al. 2014): if you can attach even crude covariates to the four mega-environments (or use a synthetic covariate), fit marker × covariate interaction and test prediction into an environment defined only by its covariates — the only model class that can predict into a *genuinely unseen* environment with no phenotypes at all.
- Compare a **factor-analytic** between-environment covariance structure (sommer) against the explicit M×E decomposition (BGLR) and note which is more parsimonious for this panel's four-environment correlation structure.
- Carve the environments into **mega-environments** (a GGE-biplot-style grouping) and ask whether predicting *within* a mega-environment is easier than across the whole target population — quantifying the payoff of mega-environment definition.
- Re-run the leave-one-environment-out evaluation on the **`DT_example` potato panel** and confirm the same qualitative story holds on independent data (a strong "this is a real effect, not a wheat artifact" signal).

## Reflection prompts (Kolb RO/AC)

- You predicted where the G×E model would help most and tied it to the crossover in your interaction plot. What did you predict, what happened in the leave-one-environment-out results, and what does the gap teach about when G×E modelling is worth its complexity?
- Random hold-out and leave-one-environment-out gave different accuracy stories. Which one would have over-promised to a breeder, and by how much? What does that say about every genomic-prediction accuracy reported without naming its cross-validation scheme?
- Which evergreen claim did this project confirm, extend, or contradict? Did watching a high-mean line turn out unstable change how you hold the "mean and stability are distinct" claim?
- Where did you have to *decide* rather than *compute* (which between-environment covariance structure, how many MCMC iterations, what counts as a meaningful accuracy difference)? Log those judgment calls — they recur in the capstone benchmark.
